## 2. Coordinator (`data/coordinator.ts`)

- [x] 2.1 Define the two outcome unions in `data/types.ts` (the module's existing type home). Newest page: `updated` / `fresh` / `no-calendars` / `too-many-calendars` / `failed` with `reason: "network" | "server" | "malformed" | "storage"`. Older page: the same failures plus `loaded` / `complete` / `unavailable` (no cursor stored yet) / `cursor-reset` / the two precondition outcomes.
- [x] 2.2 Implement `refreshNewestPage({ force }: { force?: boolean } = {})` in the exact order of D8, and comment **why** the order is the correctness argument: (a) when not forced, read state and return `fresh` if `lastSuccessfulRefreshAt` is within five minutes — this happens **before** the in-flight slot is consulted, so a freshness-satisfied passive trigger never publishes a resolved promise a later forced trigger could join; (b) `if (inFlightNewest) return inFlightNewest`; (c) assign `inFlightNewest = run()` in the **statement immediately following** the check, with no `await` between them; (d) clear the slot in `finally`, only if it is still the promise this call assigned. (Shipped shape: both slots live behind one `createSlot<T>()` factory — see the simplify-stage amendment in `design.md`; `inFlightNewest` is the as-proposed name.)
- [x] 2.3 Add an inline comment at (c) stating that inserting an `await` between the check and the assignment silently reintroduces duplicate requests and that no type or lint rule catches it — only `coordinator.test.ts`'s concurrency test does (design, Risks).
- [x] 2.4 Freshness uses `readActivityState().lastSuccessfulRefreshAt` (persisted, so a cold launch does not reset the window) compared against an **injectable now** so tests drive a controlled clock. Follow whatever clock-injection idiom the module already uses; do not add a date library.
- [x] 2.5 `unreadSince` (D4): send the stored `lastReadAt` whenever one exists, on every newest-page request. Record whether the request carried it, and set `write.unreadCount` **only** when it did — branch on the request, never on `response.unreadCount !== undefined`. Never send `unreadSince` on an older page.
- [x] 2.6 On success, build `ActivityPageWrite` and call `storeNewestPage`: `rows` mapped through the existing `dtoToActivityRow` (drop its nulls), `asOf` from the response, `heldCalendarIds` from 1.2, `nextCursor` from the response, `unreadCount` per 2.5, `lastSuccessfulRefreshAt` = the device now. This is the **only** place the freshness timestamp is written.
- [x] 2.7 Implement `loadOlderPage()` on its own in-flight slot (`inFlightOlder`, shipped as a second `createSlot<T>()` instance — see the simplify-stage amendment in `design.md`), so it can neither block nor be blocked by a forced newest-page refresh. Resolve `complete` without a request when `olderPageComplete`; resolve `unavailable` without a request when `olderPageCursor` is null; otherwise send the cursor and store through `storeOlderPage`.
- [x] 2.8 Cursor recovery (D3): an `ApiError` with status **400** on the older-page path — and only there, and only on 400 — calls `clearOlderPageCursor()` and resolves `cursor-reset`. Do **not** infer a dead chain from `asOf`, from an empty `items`, or from `nextCursor === null`; comment that `nextCursor === null` is the final-page signal and that suppressing it would restart the chain forever at the end of history.
- [x] 2.9 A 400 on the **newest-page** path is not cursor recovery (it carries no cursor). Classify it `failed/server`, record it as unexpected, and leave cursor state untouched.
- [x] 2.10 Error classification (D10): non-`ApiError` throw → `network`; `ApiError` → `server`; failed response validation → `malformed`; a throwing repository call → `storage`. Neither operation ever rejects (D11) — every path resolves with an outcome.
- [x] 2.11 Recording: `malformed`, `storage`, and the newest-page 400 record **once** through `@/firebase`'s `recordUnknownError` with a static context (`"activity/refresh"`, `"activity/older-page"`) and no payload. `network` and ordinary `server` faults are **not** recorded — they are expected on a phone and would bury real faults.
- [x] 2.12 The coordinator never writes `lastReadAt` (D11). No call to `markActivityRead` / `markActivityReadFromCache` belongs in this module.

## 5. Tests (`data/coordinator.test.ts`, `data/request.test.ts`, extend `data/repository.test.ts`)

Mock at the **mutator** (`testing.md`), not at `fetch` and not at the generated module, and use the shared `createFakeDb` for storage — never a bespoke db mock.

- [x] 5.1 **Single-flight (acceptance criterion).** Several overlapping triggers — forced and passive mixed — while one request is in flight produce **exactly one** request, and every caller resolves with that request's outcome. Drive it with a **controllable deferred** promise, never `setTimeout` or timing.
- [x] 5.2 **Freshness with a controlled clock.** Passive inside five minutes → no request, `fresh`. Passive outside five minutes → exactly one request. Forced immediately after a success → a request. A restart (`jest.resetModules()`, as `restart.test.ts` does) still reads the persisted timestamp, so the window survives a cold launch.
- [x] 5.3 **D6, newest page.** Zero tokens → **zero** requests, `lastSuccessfulRefreshAt` unmoved, outcome `no-calendars`. A stored unread count of N and cached rows both survive a refresh attempted while tokens are empty.
- [x] 5.4 **D6, older page.** Zero tokens → zero requests, and `olderPageCursor` / `olderPageComplete` are both unchanged. Add the regression assertion explicitly: after the attempt, `olderPageComplete` is still `false`. Without the guard this test fails because the server's `200`/`nextCursor: null` sets it permanently.
- [x] 5.5 **Token upper bound.** 101 unique tokens → no request, `too-many-calendars`, timestamp unmoved.
- [x] 5.6 **Unread count.** A passive refresh with a stored watermark sends `unreadSince`, stores the response's exact count, and leaves `lastReadAt` **unchanged** (this is the spec's "first-page refresh stores server unread count without moving the read watermark while the screen is closed"). A response carrying `unreadCount` on a request that sent **no** `unreadSince` does **not** write it. An older page leaves the stored count alone rather than zeroing it.
- [x] 5.7 **Cursor recovery.** A 400 on the older-page path clears the cursor, resets `olderPageComplete`, keeps **every cached row**, and resolves `cursor-reset`. A successful final page (`nextCursor: null`) marks the chain complete and is **not** treated as a reset. A completed chain issues no request. A 400 on the newest-page path leaves cursor state untouched and is recorded.
- [x] 5.8 **Failure classification and preservation.** A throwing fetch → `failed/network`, rows + unread + timestamp all unchanged, promise **resolves**. A throwing repository → `failed/storage`, resolves. An unparseable `asOf` → `failed/malformed`, **no write**, timestamp unmoved. A 503 → `failed/server`, cached rows retained.
- [x] 5.9 **Never rejects (acceptance criterion).** Assert `await expect(refreshNewestPage()).resolves.toEqual(...)` under both a throwing fetch and a throwing repository — this is the mechanism that stops a calendar-sync success becoming a failure. Add the same for `loadOlderPage`.
- [x] 5.10 **Hidden calendars are held (D9).** A device with one visible and one hidden calendar sends both tokens and supplies both ids, so the hidden calendar's cached rows survive the ownership prune.
- [x] 5.11 **Privacy negative test.** Across every recorded failure, assert the `recordUnknownError` argument contains no calendar token, cursor value, calendar name, calendar id, log id, request body, or event title/location/description. Assert `network` and `server` faults record **nothing**.
- [x] 5.12 **Query cache.** Assert the module uses no React Query client — the simplest durable form is an import-level assertion plus a test that a successful refresh leaves the query cache empty. Confirm no Activity key can reach the persisted school-selection cache.
- [x] 5.13 **Generated-contract wiring.** Assert the request body sent to the mutator matches `SearchCalendarLogsV1Dto` — correct URL (`/v1/calendar-logs/search`), `limit: ACTIVITY_PAGE_LIMIT`, tokens deduplicated, `cursor` present only on older pages, `unreadSince` present only per 2.5.
- [x] 5.14 **Prune (D7).** Extend `repository.test.ts`: removing one calendar deletes only its rows; an empty held set clears the table; the prune leaves watermark, unread count, refresh timestamp, cursor and completion flag all untouched.
