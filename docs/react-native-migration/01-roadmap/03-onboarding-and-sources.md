# Phase 03 — Onboarding & calendar sources

> **Goal:** everything that gets a calendar onto the device. This establishes **identity** (= calendar subscription tokens) and the durable storage of it — the thing the whole app hangs on.
>
> **Depends on:** Phase 02 (server-read pattern, storage). **Modules:** `onboarding`, `add_school`, `school`, `school_group`, `qr_code`, `import_ical`.

## Rough steps

1. ✅ **Onboarding flow** — landed (`add-mobile-onboarding-flow`, ADR [015](../../../docs/mobile/architecture-book/decisions/015-onboarding-flow-shape.md)) and polished as the localized welcome → agenda → notifications native carousel (ADR [036](../../../docs/mobile/architecture-book/decisions/036-native-onboarding-pager.md)). **2026-08-31 correction:** ADR [054](../../../docs/mobile/architecture-book/decisions/054-ordered-startup-and-first-launch-protected-routes.md) makes this welcome-first group the protected fresh-install gate after committed migrations, the typed Phase 09 prerequisite seam, and one atomic calendar read. Skip now confirms and durably unlocks the complete zero-calendar personal-event app. Its independent first-iCal reminder remains on Home and Calendar until import or confirmed dismissal; deleting the final calendar never reopens onboarding. Phase 09 is only an ordered no-op prerequisite in this phase, not an importer implementation. Native proof lives in `mobile/.maestro/first-launch.yaml`; device-only accessibility/layout axes live in `inbox/2026-08-31-first-launch-and-ical-reminder-device-pass.md`.
2. ✅ **School / school-group selection** — landed (`add-mobile-school-picker`, ADR [016](../../../docs/mobile/architecture-book/decisions/016-school-group-multi-select-commit.md)): grew Phase 02's read path into the **full picker** — the group step is now **multi-select with an explicit confirm-commit** (toggle leaves into a pending set, confirm persists the whole set through the unchanged identity-only store, empty confirm guarded), school search is **accent-insensitive name-or-code** via a pure `data/search.ts` helper, and completion **dismisses the whole onboarding Stack** (`router.dismissTo`). No new dependency / native change. On-device DoD axes inboxed (extended the existing `inbox/2026-06-14-school-selection-dod-manual.md`). **2026-08-30 correction:** [TIM-391](/TIM/issues/TIM-391) ([#323](https://github.com/timecalendar/timecalendar/pull/323), `a10ab396`) superseded that user path: a school row now opens the import journey's programme step. The group step remains registered and dev-deep-linkable but is reached by nothing, creates no calendar, and is neither implemented nor enabled for any production school; see [navigation.md](../../../docs/mobile/architecture-book/navigation.md) and ADR [047](../../../docs/mobile/architecture-book/decisions/047-ephemeral-calendar-import-draft.md). This is proved by the colocated onboarding draft, programme, Connect, institution-name, and manual-import tests under `mobile/src/features/onboarding/**` and `mobile/.maestro/onboarding.yaml`'s programme-step assertion, with the [import-journey device pass](../inbox/2026-08-30-import-journey-device-pass.md).
3. ✅ **QR scan** — landed (`add-mobile-qr-scan`, ADR [017](../../../docs/mobile/architecture-book/decisions/017-qr-scan-camera.md)): `expo-camera` barcode scanning (replaces `mobile_scanner`), behind the repo's first `src/features/calendar-sources/` folder (the shared QR · iCal · persistence cluster) — a pure 90%-gated scanned-value parser (`data/`, mirrors the Flutter `QrCodeResult.url` wire format) feeding a `CameraView` scanner screen (`ui/`) with permission request/denied states; `recordAudioAndroid: false` so no `RECORD_AUDIO` leaks. The camera can't be CI/Maestro-driven — the token→state wiring is Jest-proven, the on-device camera + `expo prebuild --clean` permission proof inboxed (`inbox/2026-06-15-qr-scan-dod-manual.md`). **2026-08-30 correction:** [TIM-391](/TIM/issues/TIM-391) ([#323](https://github.com/timecalendar/timecalendar/pull/323), `a10ab396`) gave QR its first normal entry point from the combined manual-import step, replacing its earlier deep-link-only reachability. `mobile/src/features/onboarding/ui/manual-import-screen.test.tsx` and the [import-journey device pass](../inbox/2026-08-30-import-journey-device-pass.md) are the verification evidence.
4. ✅ **iCal import** — landed (`add-mobile-ical-import`): grew `calendar-sources/` with a URL-entry import (Flutter `import_ical` parity — **URL-only, server-POST** via the committed generated `POST /calendars` over `customFetch`, the server owns `.ics` parsing). A pure lenient URL validator (`data/validate-url.ts`, localizable keys), accessible loading/error/retry; QR + iCal converge on one success handoff. Growth within ADR 017 (no new ADR/dep/native change). On-device round-trip + Crashlytics arrival inboxed (`inbox/2026-06-15-ical-import-dod-manual.md`). **2026-08-30 correction:** the welcome carousel's QR and URL actions were removed under ADR [036](../../../docs/mobile/architecture-book/decisions/036-native-onboarding-pager.md); [TIM-391](/TIM/issues/TIM-391) ([#323](https://github.com/timecalendar/timecalendar/pull/323), `a10ab396`) now reaches iCal URL from the manual-import step. [TIM-390](/TIM/issues/TIM-390) ([#313](https://github.com/timecalendar/timecalendar/pull/313), `5f14a146`) and [TIM-392](/TIM/issues/TIM-392) ([#321](https://github.com/timecalendar/timecalendar/pull/321), `3bba3364`) replace the `Dev import` literals with real institution/programme metadata and shared rename. Evidence is in `mobile/src/features/onboarding/draft/create-fields.test.tsx`, `mobile/src/features/onboarding/ui/manual-import-screen.test.tsx`, `server/src/modules/calendar/controllers/calendar-v1.controller.test.ts`, `server/src/modules/calendar/helpers/calendar-name.test.ts`, `server/src/modules/contact/controllers/contact.controller.test.ts`, `mobile/src/features/calendar-sources/ui/rename-calendar-dialog.test.tsx`, `mobile/src/features/calendar-sources/data/user-calendars/rename.test.tsx`, and the two 2026-08-30 [import-journey](../inbox/2026-08-30-import-journey-device-pass.md) and [rename](../inbox/2026-08-30-calendar-rename-device-pass.md) device passes.
5. ✅ **Identity persistence** — landed (`add-mobile-calendar-identity-persistence`, ADR [018](../../../docs/mobile/architecture-book/decisions/018-user-calendar-storage.md)): a durable **Drizzle** `user_calendars` token store (MMKV genuinely weighed and rejected — relational identity + Phase-09 importer target + free migration-runner durability), the schema mirroring the Flutter `toDbMap()` **verbatim** (importer fidelity — `id`-is-record-key, `token` the irreplaceable identity, dates TEXT ISO-8601 UTC, `visible` boolean), the second real migration committed, the full `data/user-calendars/` layer (mappers + repository + reactive hook + the shared `addCalendarFromUrl` persist seam), and ships 3/4's success paths rewired to persist durably (the ephemeral holder removed). On-disk restart/kill/cache-clear durability is the on-device manual pass (HUMAN: `inbox/2026-06-16-calendar-restart-durability.md`). **The Phase-09 importer-target schema is in place to receive the recovered `user_calendars.token`.** **2026-08-30 correction:** [TIM-392](/TIM/issues/TIM-392) ([#321](https://github.com/timecalendar/timecalendar/pull/321), `3bba3364`) makes calendar names converge across installations through a name-only sync write that preserves the local `visible` flag. `mobile/src/features/calendar/data/sync/sync.test.tsx`, `mobile/.maestro/user-calendar-rename.yaml`, `mobile/.maestro/rename-seed.yaml`, and the [rename device pass](../inbox/2026-08-30-calendar-rename-device-pass.md) prove the boundary.
6. 📥 **Confirm Android storage** — needs physical Android hardware, so it's a HUMAN inbox item, not a ship (`inbox/2026-06-15-android-storage-verification.md`): verify the open Android items from the [migration research §6](../00-exploration/data-persistence-migration.md#6-device-verification-done) (prefs backend + sembast path) on a real Android device. It gates the Phase-09 importer, not any Phase-03 feature.

## Exit criteria

- ✅ A fresh user can add a calendar through the shipped **school → programme → Connect → QR or iCal URL** path. [TIM-391](/TIM/issues/TIM-391) ([#323](https://github.com/timecalendar/timecalendar/pull/323), `a10ab396`) is the corrected journey; the dormant group step is not an add-calendar path. [TIM-390](/TIM/issues/TIM-390) ([#313](https://github.com/timecalendar/timecalendar/pull/313), `5f14a146`) supplies the creation contract, and [TIM-392](/TIM/issues/TIM-392) ([#321](https://github.com/timecalendar/timecalendar/pull/321), `3bba3364`) supplies rename and convergence. The named Jest, Maestro, and device-pass evidence is cited in steps 2–5. The earlier paths remain built, typed, lint-clean, unit/component-tested, i18n FR/EN, and accessible; Maestro E2E was green on both platforms at commit `26ba25d`, run 27582517604. The per-feature on-device DoD axes remain inboxed in each feature's `*-dod-manual.md`.
- ✅ Calendar **tokens persist across restarts** — durable Drizzle `user_calendars` store (step 5), restart-simulation + repository + mapper-fidelity Jest tests green; **schema is migration-ready** (mirrors the Flutter wire format verbatim, the Phase-09 importer target). On-disk restart/kill/cache-clear durability is the inboxed on-device pass (`inbox/2026-06-16-calendar-restart-durability.md`) — no list UI ships this phase, so there is no observable surface for a Maestro restart assertion; the Jest restart-simulation + the on-device manual pass are the proof.
- 📥 **Android storage paths confirmed** — inboxed HUMAN item (step 6); needs physical hardware.

**Phase 03 status: COMPLETE (autonomous feature work).** All five feature ships landed on `main` (PRs #165, #167, #168, #172, #173), each through the full plan→apply→simplify→review→archive pipeline with an APPROVE gate, and the on-`main` Maestro E2E is green on both platforms. The only remaining items are **irreducibly-human on-device/hardware passes** (the per-feature DoD device axes, on-disk restart durability, and the Android storage-path confirmation), all inboxed — none are blockers per the loop/DoD inbox convention. **2026-08-30 amendment:** the completed current path is the import journey documented above, not group selection: [#313](https://github.com/timecalendar/timecalendar/pull/313) (`5f14a146`), [#323](https://github.com/timecalendar/timecalendar/pull/323) (`a10ab396`), and [#321](https://github.com/timecalendar/timecalendar/pull/321) (`3bba3364`) are the final implementation evidence.
