# Testing

The testing rules for `mobile/`. R-1 pointer convention: entries point at the live gate, file, or spec that enforces a rule rather than re-deriving it, and carry only the caveats tooling can't.

## Unit / component harness — `jest-expo`

- **`jest-expo` preset** owns the transform/ignore lists (the RN failure mode the preset exists to prevent — no hand-rolled transform config). `@testing-library/react-native`; tests colocated as `*.test.ts(x)` next to source. `npm test` = `jest --ci`, the same entrypoint locally and in CI (like lint).
- **Mock at the `customFetch` seam, not the network.** Data-layer tests `jest.mock` `src/api/mutator` and drive the _real_ generated Orval hook + a real `QueryClient` — the mutator is the designed seam (see Data layer), so mocking there exercises everything above it without a server. `src/features/school-selection/data/queries.test.ts` is the reference. The posture is two-layered: the feature `data/` suite owns the mutator-mock proof, and the presentational `ui/` screen suite above it mocks the feature's own `data/` hook (keeping the pure helpers real via `requireActual`) — e.g. `school-picker-screen.test.tsx` mocks `useSchools`, not the mutator, because the hook→DTO mapping is already proven a layer down.
- **Mock the `@/db` seam via the shared `src/test-support/fake-db.ts` (`createFakeDb`).** Repository + restart tests `jest.mock("@/db", () => mockFake.module)` against one stateful, spy-instrumented Map-backed fake instead of hand-rolling the query-builder per file — its `spies` serve the query-shape assertions, its per-table stores survive `jest.resetModules()` for the on-disk-survives-a-restart proof, and `seed()`/`reset()` drive read rows and `beforeEach`. Consumers MUST name the instance `mock`-prefixed (`const mockFake = …`) so `babel-plugin-jest-hoist` lets the hoisted factory close over it.
- **Coverage** is collected via `npm test -- --coverage`. The `coverageThreshold` is **enforced** — 90% logic / 70% global; see [ADR 003](./decisions/003-coverage-threshold.md). Gated by the `test-mobile` job (R-1).
- **An explicit per-test time budget — `testTimeout: 30000` ([ADR 044](./decisions/044-jest-per-test-time-budget.md)).** RN/Expo host components register lazily on first render, so the one-time cost lands on whichever test mounts them first; ADR 044 is the canonical record of the load-regime measurements and sizing rationale. `mobile/jest.config.test.ts` guards the key against drift (floor 20 000 ms), the way `app.config.test.ts` guards config shape in the same job. **The budget bounds how long a test may take to execute; it is never a reason to lengthen a `waitFor`/`findBy`, add a retry, or weaken a matcher** — settling a red test that way converts an intermittent into an invisible one.
- **Restore every `Platform.OS` override before the next test, including when the overriding test throws.** `usePlatform` from `src/test-support/platform.ts` is the mechanism for a `describe`-scoped override; a `try`/`finally` that restores the captured original is equally conforming. Tests must not call `jest.replaceProperty(Platform, "OS", …)` inline in an `it`, and must not rely on `jest.restoreAllMocks()` for the restore — the latter would also discard the suite-wide `AccessibilityInfo` spies from `jest/setup-splash.ts`.

## E2E — Maestro, real round-trip

- **Real data, deep-linked.** A Maestro flow under `mobile/.maestro/` launches the dev-variant app, opens a `timecalendar-dev://…` deep link, and asserts seeded data renders — proving app → generated client → `customFetch` → NestJS → Postgres end to end, nothing mocked. Flows are shared across platforms (stable seeded-text assertions, no per-platform selectors).
- **The seeded-token round-trip pattern (ADR [030](./decisions/030-dev-import-deep-link-runtime-gate.md)).** The startup sync no-ops on an empty `user_calendars` table, so a flow must first make the app durably HOLD the seeded token. The shared `mobile/.maestro/import-seed.yaml` preamble does this: `- runFlow: import-seed.yaml` opens `timecalendar-dev://dev-import?token=e2e-smoke-calendar` (the dev-only import route — resolve → durable upsert → sync → route to `/calendar`), so the caller can assume a synced calendar from step one. The four calendar-family flows (`calendar` / `home` / `event-checklists` / `hidden-events`) begin with this preamble and assert **real synced data**: a seeded tile → tap → real details, the today timeline, a checklist add/toggle/delete round-trip through `checklist_items`, a hide→gone→un-hide→reappears round-trip. Seeded titles are ASCII-safe and unique per flow (`E2E Today Lecture` for details/checklist, `E2E Today Seminar` for hide/un-hide — `server/src/scripts/seed-e2e-calendar.ts`).
- **`clearState`-first, because durable state leaks across flows.** The harness runs each top-level YAML in a fresh Maestro process, but `stopApp` and process isolation do **not** clear app data — the import writes a durable SQLite token. So `import-seed.yaml` opens with `launchApp: clearState: true` before the deep link, wiping the store so one flow's token/hidden-set/checklist rows can't pollute a later flow's empty-state assertions. Grid tiles carry no per-event testID (the calendar-kit worklet grid owns tile layout), so flows assert/tap synced tiles by **unique seeded title text** on the **agenda** list; uuid-suffixed row testIDs (checklist) are matched by `.*` regex with a single row + the typed content text. The e2e device runs in **EN**, so localized taps (the hide chooser, un-hide) use EN strings — the established convention (`settings.yaml` asserts "Settings"). The UTC-"today" seed caveat is recorded in `mobile/e2e/README.md`.
- **Single-command, process-per-flow run (ADR [038](./decisions/038-isolate-maestro-flow-lifecycles.md)).** `mobile/e2e/run_e2e.sh` performs lifecycle `up` once → one `maestro test <top-level-yaml>` process per lexically ordered flow → lifecycle `down` once (teardown on success _and_ failure), with `--keep-up` (debug escape hatch) and `--native` (passthrough). Attempts default to one. Only iOS CI passes `--startup-attempts 4`, and the retry class is **structural, not signature-based**: `mobile/e2e/classify-maestro-attempt.mjs` reads Maestro's own per-flow `commands.json`. Captured-output assertion evidence wins globally; any command that reached `FAILED` before the final startup failure remains globally terminal. Otherwise the latest explicit `launchAppCommand` / `stopAppCommand` / `openLinkCommand` at the failing command's depth begins the final restart epoch. A `COMPLETED` assertion before that boundary may belong to a successful earlier phase; from the boundary onward, an evaluated assertion or non-startup interaction is terminal, while an epoch containing only startup commands and non-evaluated assertions is retryable. No record means the session died before opening the flow; an unreadable record fails closed. Every retry reruns the entire top-level flow in a fresh Maestro process. A deterministic launch failure still exhausts the four attempts and exits non-zero, so retry costs attempts, never correctness. The wrapper does **not** build/install the app: a release-config dev-variant binary must already be installed (see `mobile/e2e/README.md`).
- **Flow selectors resolve against the shipped app, enforced in the BASELINE gate.** `mobile/e2e/maestro-selectors.test.ts` fails when a flow's `id:` selector matches no `testID` under `mobile/src`, naming the flow, line, and id. It lives in the baseline gate on purpose: the native gate is on-demand, so a UI rework that deletes a `testID` merges green and the break surfaces one expensive native run later — and because `run_e2e.sh` stops at the first failing flow, one stale id masks every later flow (three had accumulated by TIM-264). Matching is not a literal comparison, which would misreport seven working ids here: a flow `id:` is an anchored **regex**, a `testID` counts whether written `testID="x"` or as an object property `testID: "x"`, and a template-literal `testID` stands for its family. Never allowlist a false positive — that disarms the guard permanently. The calendar family reaches the agenda through the `calendar-view` control (one testID for the iOS `@expo/ui` picker and the Android menu trigger) plus its locale-stable "Agenda" entry; controls that can carry no testID at all (the native-header search bar — `react-native-screens`' `SearchBarProps` has no such field) are addressed by their EN label, consistent with the EN-device convention above.
- **A seeded-title text selector must match every surface that renders it, enforced in the BASELINE gate.** The second guard in `mobile/e2e/maestro-selectors.test.ts`. An agenda tile (`agenda-list.tsx`) and a home today-timeline tile (`today-timeline.tsx`) are Pressables with `accessibilityRole="button"` plus an `accessibilityLabel` that **extends** the title — `{{title}}, {{time}} {{location}}`. XCUITest collapses such a container into one element and drops the child text, so on iOS the tile exposes only that composed label. A Maestro text selector is a **fully anchored regex**, so a bare `"E2E Today Lecture"` matched nothing on a screen that plainly showed the event, and `hidden-events.yaml`'s `assertNotVisible` passed **vacuously**. Write these selectors as `"<title>(,.*)?"`: one cross-platform form matching the composed label on iOS and the bare text node on Android, with no platform fork and no loss of strength (it still cannot match a different title sharing the prefix). This is a distinct class from a stale id and from a below-the-fold control — the id guard is _correct_ to stay silent, because every `testID` and every rendered string genuinely exists; only the iOS projection differs. The guard reads the titles from `server/src/scripts/seed-e2e-calendar.ts` and the label templates from `en.json`, so it re-checks itself when either changes; a label that _is_ the title (school and personal-event rows) or one that _wraps_ it (`Un-hide {{title}}`, a separate control) is deliberately out of the rule.
- **Shared server lifecycle.** The server half is owned by `ci/e2e-server.sh` (compose-first, `--native` for Docker-less macOS) — the same lifecycle the Flutter harness uses. See the `e2e-server-lifecycle` spec; do not re-hand-roll server boot/seed/teardown in a harness.
- **Local server dependencies.** OpenAPI generation and server tests that need backing services use `bin/server-compose.sh up -d postgres redis` from the repository root. This is the reusable nginx-free prerequisite; alternate `TIMECALENDAR_POSTGRES_PORT` / `TIMECALENDAR_REDIS_PORT` values require matching test-profile `DATABASE_URL` / `REDIS_URL` values on the server command. This local entrypoint does not replace `ci/e2e-server.sh`, which retains ownership of E2E boot, seed, logs, and teardown.
- **E2E builds are release-config, no Metro, with an explicit local-backend contract.** CI builds on GitHub runners via `expo prebuild` + native tooling (Android: Gradle `assembleRelease` → `adb install`; iOS: `xcodebuild -configuration Release -sdk iphonesimulator` → `simctl install`) — never EAS, never debug+Metro. Every prebuild and release-compilation step explicitly sets `APP_VARIANT=development`, `BACKEND_ENVIRONMENT_CAPABILITY=development`, and the platform-local `EXPO_PUBLIC_API_URL`: `http://10.0.2.2:3005` (Android emulator → host) / `http://localhost:3005` (iOS simulator). `mobile/e2e/test_ci_mobile_e2e.sh` enforces the complete step-scoped contract.

## Dev-variant network exceptions

- **Local-server access rides the `development` variant only**, in `app.config.ts`: Android `usesCleartextTraffic: true` (via `expo-build-properties` — release builds block cleartext HTTP by default, which would silently break the `10.0.2.2` call) and iOS `NSAppTransportSecurity.NSAllowsLocalNetworking` (belt-and-braces over ATS's loopback exemption). **Production identity is untouched — the store app can never talk cleartext.** Verified by `expo config --json` diff between variants; can't be a lint rule (config-shape, not source), hence this prose (R-1).

## CI topology

- `test-mobile` runs gen-drift, tsc, lint, then Jest. `e2e-mobile-android` (ubuntu, KVM emulator, reuses the `build-server` image artifact via `E2E_SERVER_IMAGE`) and `e2e-mobile-ios` (macOS runner, Postgres/Redis provisioned natively because GitHub macOS runners have no Docker — the `--native` seam). Both upload Maestro debug output + server logs on failure (R-1).

### Workflow split + on-demand E2E

Workflows are split by concern; native E2E is **not** run on every push (cold native build + device boot is ~20–30 min/platform — toolchain cost, not app size).

- **`ci-build-deploy.yml`** — server/web images, server tests, deploy (every push; deploy self-gates to main/production).
- **`ci-mobile.yml`** — `test-mobile` (gen-drift, tsc, lint, Jest); path-filtered to `mobile/**` + `openapi/**` + **`.github/workflows/ci-mobile-e2e.yml`**. It also runs `test_run_e2e.sh` and `test_ci_mobile_e2e.sh` — pure bash + node, no device. Both proofs guard `ci-mobile-e2e.yml`, whose own jobs are label-gated, so a PR editing only that file would otherwise run **no** gate and land the break on `main`. The proof must live in a workflow that watches the file it proves; this is the same treatment, for the same reason, as `maestro-selectors.test.ts`.
- **`ci-mobile-e2e.yml`** — `e2e-mobile-android` + `e2e-mobile-ios`, **on-demand**: PRs only with the **`run-e2e` label**, always on main/production when mobile/openapi changed. Self-contained — builds its own server image (`cache-from: type=gha`, a fast hit when `ci-build-deploy` already built that SHA) since artifacts don't cross workflow runs. The Android job inherits the label gate via `needs: build-server`.
- **`ci-flutter.yml`** — legacy `test-app` + Flutter `test-e2e`, demoted to main/production pushes touching `app/**` (R-5 bounded maintenance).
- **Branch-protection caveat:** path-filtered jobs that are skipped don't report a status — if any of these become _required_ checks, a skip can block a PR. None are required today.

## Recorded debt — CI E2E caching speedups (not yet done)

Native E2E runs cold every time in CI (local builds are fast only because Gradle/DerivedData/Pods caches persist on disk). Deferred speedups: ① **AVD snapshot caching** for the Android emulator (skip cold boot); ② **iOS DerivedData cache** keyed on the lockfile (point `xcodebuild -derivedDataPath` outside the `prebuild --clean` tree so it survives); ③ confirm the **Gradle build cache** (not just deps) is active. Realistic gain ~Android 28→18 min, iOS 18→10 min on warm caches. Orthogonal to the on-demand split above. **Trigger:** when E2E run time becomes a friction point. Roadmap mirror: `docs/react-native-migration/01-roadmap/01-foundation.md` step 5.

Same class, the unit gate: **CI restores no Jest transform cache** — `ci-mobile.yml` caches npm only, so every `test-mobile` run pays the full cold transform, which is what put the harness's first-render cost against the per-test budget in the first place ([ADR 044](./decisions/044-jest-per-test-time-budget.md)). Caching Jest's `cacheDirectory` keyed on the lockfile would cut both the run time and the headroom problem at its source. Out of scope where it was found (TIM-273 excludes `.github/workflows/**`). **Trigger:** the next time the gate's wall clock or its timeout headroom becomes a problem.
