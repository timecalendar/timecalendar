# E07 P01 Android native snap prototype

Status: **P01 fails on the OnePlus 6.** Two bounded, Android perf-app-only React Native 0.85.3 ScrollView prototypes improved some rapid chains, but the exact lifecycle candidate missed one of twenty forward pages in its first physical run. The prototype branches are experimental and are not part of the production app or a release candidate. The owner authorized this scoped prototype on 2026-10-02; [D01](../decisions/D01-native-scrollview-paging-owner.md) and [D08](../decisions/D08-delivery-gate-and-rollout.md) retain the production architecture and release gate.

## Native chronology

The baseline capture matched eighty virtual-HID tracking-ID down/up pairs to eighty distinct native release event times across the four scenarios; kernel ups and native releases differed by at most 1 ms. Twenty unique pre-intercept `ACTION_DOWN` event times appeared per scenario after deduplication. The scroller was unfinished at 19/20 forward, 19/20 backward and 17/20 reversal downs in the second baseline run. One baseline snap began 465 physical pixels from its chosen target and advanced only 27 pixels before the next down 113 ms later. Rapid release velocity was zero in all forward and backward snaps. This establishes interrupted low-velocity native snap travel, not the behavior of a genuine high-velocity fling.

The first policy candidate retained one unfinished target and used native `OverScroller.startScroll` from the current visible offset for a distance-scaled 16–96 ms low-velocity snap. It generated only sixteen snaps for twenty releases in each straight chain. Source inspection and event order support a stale post-touch-runnable mechanism: after a fast snap, the next down sometimes reached `onInterceptTouchEvent` but not `onTouchEvent`; the old runnable could then consume the next release and end at an unaligned offset. This is a source-and-trace inference, not a counterfactual proof.

The lifecycle candidate cancels that runnable at the perf pager's pre-super `ACTION_DOWN`, after preserving the one unfinished target. Its initial run recorded twenty native snaps for twenty releases in each rapid scenario, and the repeat did too. Eighteen initial and nineteen repeat snaps used the retained target. No chosen target was more than one interval from the release offset; the largest observed target gap was 0.633 interval across these runs. The native animation durations in the straight chains were 44–57 ms. No retained-target reversal occurred, so that branch's reversal semantics are unproved despite the observed return to origin.

`onInterceptTouchEvent` also recorded single-pointer `ACTION_CANCEL` (`action=3`, pointer count 1) in half of the straight drags. The prototype conservatively treated these as multi-pointer/cancellation and used React Native's original slow fling path for those snaps. The single-pointer cancellation correlates with the split native paths; its origin and contribution to the one missed forward page are **not proven**. The logs do not justify removing cancellation protection, because a real canceled gesture or pinch must still invalidate a pending target.

## Physical scenario results

The unmodified `mobile/perf/run.mjs` injected each four-scenario sequence in one app process. Its rapid script uses twenty 150 ms strokes with 150 ms configured gaps, reversal uses ten forward/back pairs with 120 ms configured gaps, and diagonal uses twenty 30-degree strokes with 1,200 ms configured gaps. These are observed page-control endpoints after settling; gesture attempts alone are not counted as successful pages.

The lifecycle initial run recorded eighty kernel virtual-HID down/up pairs and eighty native releases, twenty per scenario. Its page-control witness was Monday 5 October 2026 to Monday 15 February 2027 after the forward chain, then Monday 28 September after the backward chain. The repeat went from Monday 5 October to Monday 22 February and returned to Monday 5 October. A subsequent six-gesture vertical scroll and three-second two-pointer pinch left the page control on Monday 5 October and produced no horizontal native release or snap. The pinch generated a native pointer-down with count 2. A final Android UI hierarchy showed that page control, a visible `MON 5` date heading, and nonzero Calendar canvas and week-page bounds. It did not show event tiles. Matching title, header, dates and events at **every** intermediate settle remains unknown.

The achieved rapid scripts took about 7.1 seconds each versus 5.9 seconds of planned HID frames. [P01](../product.md) does not specify a total-chain time threshold; this timing is descriptive. The lifecycle initial native trace had unfinished scrollers at 9/20 forward, 10/20 backward and 10/20 reversal downs, versus 19/20, 19/20 and 17/20 in the baseline repeat. The scripts therefore do not prove that **every** new touch preceded the prior app settle; native scroller completion is not itself proof of app settlement. The initial lifecycle run's +19 endpoint independently fails the required exact twenty-page movement. The traced lifecycle run's diagnostic frame p99 was 26 ms forward/back, 21 ms reversal, 65 ms diagonal and 31 ms during pinch; one pinch frame exceeded 33 ms. Tracing, incomplete named measurements and the failed P01 result prevent any P02 pass. The short/slow drag, genuine high-velocity one-page fling, deliberately canceled mid-page touch, physical TalkBack/VoiceOver, clean-frame, long-session heap/view and owner release checks were not completed for this failed prototype.

## Bounded verdict

The experimental native patch stays on `calendar-paging-p01-native-policy` and `calendar-paging-p01-native-lifecycle`; neither branch is a production change or an accepted repair. A future scoped experiment would first establish the origin of single-pointer intercept cancellation and distinguish it from genuine touch cancellation and multi-pointer pinch before changing the policy. It would then need exact-revision repeated 20/20 chains, carry-under-reversal, short/slow and high-velocity flings, full visible-state agreement, accessibility and the named P02/P03 gates. [E07 release evidence](E07-release.md) remains blocked, and the owner has not issued an exact-revision release verdict.
